# Filer replication progress: remove archived colorstring dependency

Status: LOCAL QUALIFIED PATCH PROPOSAL BASED ON GENERATION30, FOR A FUTURE CANDIDATE (CURRENTLY PLANNED32). The historical scratch folder name31 is not the active candidate sequence. Active generation31 is the separate nested-Kafka module cleanup. No release image, deployment or target qualification is claimed. The frozen generation30 source and evidence are unchanged.

The only compiled importer of archived `github.com/mitchellh/colorstring` is `github.com/schollz/progressbar/v3`. The latter is imported at one SeaweedFS callsite, `weed/replication/sink/filersink/fetch_write.go`, for a cosmetic copied-chunk counter. The existing upstream v3.19.1 pin remains the latest release and still imports colorstring; a generic upgrade does not remove this chain.

The patch replaces that display dependency with a small SeaweedFS-owned plain-text reporter. It keeps the two original success-only progress calls, one after a manifest chunk is copied and one after a normal chunk succeeds. Executor scheduling, retries, errors, copied data and size checks are unchanged. Its mutex serializes concurrent increments and writes; completion saturates and emits one final newline. It creates no goroutines. Display errors remain cosmetic, as the previous callers also ignored `ProgressBar.Add` errors.

The display is deliberately different: a plain `filename: copied/total chunks` counter remains visible at completion, instead of a full-width bar with time estimate that clears on completion. The counter stays on stdout, preserving the original progress bar stream; the final newline now follows it on stdout rather than the old separate stderr callback. No colors or ANSI escape commands are generated by the reporter. No target feature is removed.
