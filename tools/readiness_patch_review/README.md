# Offline Ingestion patch review compiler

This is a single-use private review-template compiler. It reads only the exact captured input context, completed predecessor journal/review/packet and the four verified public candidate files. It rehashes the candidate archive and checks captured snapshot/metadata identities. It never opens a socket, instantiates Engine, runs Docker, calls an owner/database/provider, opens bearer/private-key files, or grants runtime authority. A fixture test forbids socket creation during the full compilation path.

Full prior-frame equality uses the frozen qualified replacement validator from ouf-deploy@5e08760666e177a971a5c466955e4376d10c54ef. Two imports are redirected to hash-pinned local support modules; domain comparison logic remains unchanged. The frames helper is preserved, and input_reader is the exact89ef210 source (SHA256c97ae9...). The original114-module executor graph and loader are untouched. Helper modules are compiled from the same verified in-memory bytes, not reopened after checking. This provenance and three helper SHA256 values are explicit in compiler.py.

The compiler checks the *captured* current Ingestion configuration against the original admitted frame with restored restart policy: full Config/environment/image defaults, mounts, HostConfig, endpoints/IP/MAC/aliases, generation and source image. Candidate defaults must remain compatible; a changed Env, inherited field or label default blocks compilation. The previously qualified Linux image-only ArgsEscaped omission rule is retained only with explicit Entrypoint/Cmd and Linux. No other mismatch is normalized.

The proposed frame preserves captured environment, Cmd/Entrypoint/User, mounts and network allocations. Only Image and source revision label change semantically; Docker-generated hostname/MAC metadata is normalized using the already-qualified endpoint rules. Restart policy is temporarily no during replacement and restored afterward. A new deterministic operation reference binds current container ID and exact new image ID. Planned steps include fresh gates, image import, disable/stop/detach/retain/create/start Ingestion, readiness and final checks, and restart-policy restoration. Gateway and other services have no lifecycle/write stages; no database migration, grant or source activation is allowed. Normal configured runtime work may resume when the service starts; this is disclosed in the private template.

This template is NOT an executable authority or a qualified native patch executor. It must still receive separate native executor qualification, fresh infrastructure consent and current HUMAN/owner/database/runtime/route gates before any apply. The dedicated workload route must be verified under qualified transport. The compiler does not reverify live runtime, owner control or database admission; its public receipt explicitly reports those limits. The proposed900second maximum is not a new active window.

A new root-owned0700 review directory contains0400 claim/review/complete files. Parent and claim entries are fsynced before completion. Predecessor and input files are never rewritten. Repeated or ambiguous compilation stops without overwrite; preserve every claim and reconcile separately. Archive rehashing and all I/O have finite bounds and a55second deadline. Public output contains only hashes, resource references, stage counts and limits; private OCI values stay inside review.json. SHA256 support checks are not human approval.
