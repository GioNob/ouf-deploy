La classificazione riguarda il workflow intero. Un input Actions di una run passata, un’immagine di una consegna identificata o il confronto con i byte già consegnati rendono storica la prova. Un checkout fissato per riprodurre una fixture, un test datato, una cache di compilazione o un artefatto scambiato fra job della stessa run possono far parte della CI viva. Nei casi dubbi gli eventi esistenti restano attivi. La data nel commento è la data d’autore del commit che ha aggiunto il file nella storia Git locale.

**P** indica `push`, **PR** indica `pull_request`, **D** indica `workflow_dispatch` e **C** indica `workflow_call`. Le colonne riportano gli eventi. Per consultare i filtri originali di percorso e branch usare `git show 56ecbc2e:.github/workflows/<file>`. La classificazione deriva dai job e dai loro input. Gli errori HTTP e la cache Trivy mancante sono quelli segnalati sulla PR.

## Avvio e guardia

Per avviare una qualificazione storica aprire **Actions → Run workflow** e selezionare la revisione desiderata. I job che leggono artefatti originali richiedono ancora quei byte. Le quattro coorti Storage 29, 31, 32 e 33 passano ID e digest prodotti dal proprio job ai rispettivi laboratori riusabili. Ciascun laboratorio accetta solo `workflow_call`. Sostituire quell’interfaccia con il dispatch invaliderebbe il job chiamante. L’avvio manuale avviene dalla coorte. La guardia controlla anche gli ingressi ai quattro laboratori nel repository.
