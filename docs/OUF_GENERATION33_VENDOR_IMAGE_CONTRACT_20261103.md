# Generation33 vendor-image contract: preparatory design

Status: preparatory verifier code, not an image qualifier. No generation33 build manifest, image, scanner result, SPDX or producer receipt is supplied. Actual hosted vendor observations must precede a pinned manifest and full image-enginev4 implementation. Frozen enginesv1–v3 and candidates31/32 are unchanged.

`tools/storage_security/generation_vendor_contract.py` provides small independently tested validation functions for the future engine. It binds the real generation32 parent manifest (`5289372fe7577936376497adba277fb329bb2a625652eacad47c854735937144`), distinguishes root source patches from dependency patches, verifies complete origin-set coverage, vendor file-tree deltas, vendor execution requirements and compiled dependency exclusions. It cannot authenticate ZIP archives by itself or replace producer attestation and independent readback.

The frozen generation32 parent uses the corrected indexed Git tree `80632ef3a54debb04531c1913860d2f94d2b418d`, which includes all4,567 source entries. The correction restores24 upstream tracked files omitted only by the previous empty-index measurement; those file bytes were always present, and binary/compiled graph identities are unchanged. The earlier failed observation remains historical evidence.

## Two source domains

The future explicit schema is `ouf.seaweedfs-generation-vendor-build-manifest.v1`:

- `generation=33`, `sourcePatchCount=32`, `dependencyPatchCount=1`.
- `orderedSourcePatches` equals the complete frozen32 prefix byte-for-byte. The original source Git tree and root go.mod/go.sum hashes remain those of generation32.
- `orderedDependencyPatches` contains the separate Iceberg v0.7.0 vendor patch (`001459c5254303378cb30dafaceec1777cbb143957fa6afb5e2e7eb8cbb46eef`). It is not presented as a fictitious33rd patch to the upstream SeaweedFS Git tree.
- Before/after vendor tree SHA256 values, vendor/modules.txt SHA256 and full file count are independently pinned. All file paths and hashes are checked; the reviewed Iceberg config/config.go must be the only changed vendor file.
- Actual binary, graph and raw vendor build-info hashes are new facts. No generation32 binary identity or image outcome transfers.

Root Git tree reconstruction must preserve the upstream tracked-file index: apply the exact source patches with `git apply --index` from a seeded upstream index. An empty alternate index followed by `git add -A` can omit tracked files matching ignore rules and is not an acceptable tree oracle. File-byte inventories and indexed-tree parity are distinct checks.

The source observer supplies `vendor-before-files.json` and `vendor-after-files.json` as complete relative-path→SHA256 maps. The contract recomputes both tree hashes and binds the original file-authentication report. Vendor/modules.txt is generated by Go and bound separately; every other original vendor file must match a member of an authenticated input ZIP. Original LICENSE/NOTICE preservation remains enforced by the dedicated YAML source verifier.

## Original inputs and patched bytes

`baseline-vendor-origins.json` covers every module enumerated by vendor/modules.txt, including modules outside the compiled binary. Its `buildInfoSha256` explicitly binds `baseline-vendor-module-enumeration.txt`, whose heading says **NOT binary build-info**. `compiled-module-origins.json` instead binds the real vendor binary's build-info. Both tables must be complete, unique and consistent, and the compiled table must be the exact module/version subset of the full vendor table. Both bind the frozen root go.sum.

The companion collector verifies original module ZIP and go.mod h1 values and their SHA256 digests against the locked original inputs. The observer also runs `go mod verify` before/after and checks each baseline vendor file against its original ZIP member. A second clean vendor materialization and binary build must reproduce the same bytes. The contract consumes these bound records, but deliberately does not claim to have performed the cryptographic archive checks itself.

Vendor build-info legitimately omits module h1 values. The verifier rejects inserted h1 values and module replacements; original input h1 values live only in the separate origin tables. They never describe the patched vendor source. Iceberg remains canonically identified as github.com/apache/iceberg-go@v0.7.0, with an explicit downstream source patch; the YAML module remains go.yaml.in/yaml/v3@v3.0.5.

All root build/list/test/race/denied-profile commands must explicitly use `-mod=vendor`, with empty GOFLAGS and GOWORK=off. `-modfile`, overlays, conflicting module modes and missing command roles are rejected. Nested modules need their own observed contracts; this preparation does not silently change their module mode.

## Future image and readback integration

The new image enginev4 must use the established immutable image-format primitives and fresh generation33 scanner/provenance checks, together with this contract and the companion YAML source/origin verifiers. The generation32 qualifier must not be rebound or patched in place. Its image outcomes are historical.

Fresh raw Trivy and SPDX data must retain canonical upstream module names/versions and be checked against the complete actual binary inventory. A separate modified-dependency-source supplement binds the raw scan/SPDX hashes and IDs, original input, applied patch, before/after source trees and resulting binary. It must not rewrite upstream h1 values, the scanner findings or raw SPDX bytes, and must not claim to be an independent SPDX document.

The future archive/readback schema must explicitly enumerate additional vendor materials, root go.sum and the separate provenance supplement. Frozen22-member readers cannot silently accept an expanded archive. The reader must recheck exact source/tool hashes, complete origin coverage, both vendor inventories, the execution record and canonical raw inventory, then reproduce the new assessment. This wiring is intentionally not supplied before actual observations; no arbitrary artifact IDs, hashes or success records are invented.

Every normal image gate remains necessary: fresh HIGH/CRITICAL/UNKNOWN findings are held, required hosted shell/TLS cases must pass, and licence/cohort, durable custody and cold recovery/MIME/identity/egress are newly bound. Removing compiled legacy YAML is not an all-maintained claim. Downstream technical ownership and review cadence remain explicitly OPEN; release admission/runtime authority stay false and target operations remain0.

## Local validation

Nineteen small tests cover missing origins, incomplete full-vendor coverage, compiled subset drift, conflicting original-input checksums, original-parent mutation, source/dependency-count confusion, missing vendor hashes, unsafe paths, unreviewed source changes, incomplete file authentication, non-vendor or overridden command modes, forged vendor h1 values, replacements, legacy YAML/reintroduced exclusions, wrong canonical versions and authority inflation. The positive fixtures are explicitly synthetic unit data; they are not generation33 observations. No full vendor operation, heavy build or network download was performed by this task.
