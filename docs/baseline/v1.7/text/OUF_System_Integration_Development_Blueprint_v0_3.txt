6. MCP implementation position
“Do not modify MCP Server” means the frozen v1.1 design is not reopened. It does not mean that MCP implementation is omitted. The Development WBS v0.4 therefore contains an explicit MCP stream.
Java 21 / Spring Boot modular monolith; mcp-server and maintenance-worker profiles.
Canonical Capability Manifest and typed DTO validation.
PostgreSQL/Flyway Agent Budget Store; multi-Pod cumulative budget semantics.
RetryLoopGuard and explicit remediation without automatic capability redirect.

MCP-A acceptance suite, including protected-operation isolation tests.

9. Release and acceptance gates
Contract gate: shared schemas, OpenAPI, examples and compatibility checks pass.
Build/security gate: Java 21/platform BOM, unit/static/security/secret scans pass.
Database gate: Flyway migrate from zero and supported upgrade paths pass where persistent.
Integration gate: scenario-neutral identity, Gateway/backend security chain and cross-module contract assertions pass.
E2E gate: canonical OUF-E2E catalogue and module-specific MCP-A/THS-A/PET suites pass or are explicitly blocked only by external platform gates.
Operational gate: Helm lint/template in target CI, probes/network policies, observability, SBOM/image digest, recovery and runbook evidence pass.
Representative acceptance gate: real platform bindings PLAT-01..08 are installed and tested.

No duplicate canonical E2E identifiers.
