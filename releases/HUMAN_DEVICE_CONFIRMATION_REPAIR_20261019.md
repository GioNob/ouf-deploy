## New callback API

`HumanSession.login(emit=..., stop=..., confirm_browser=callback)` accepts a callback receiving only verificationUri, userCode, deviceDeadline and attempts. It must return exactly True; an early confirmation spends at most one token poll before another confirmation is required. No callback leaves DEVICE_POLL paused. Every confirmation is bound to the exact retained row; concurrent changes require a fresh confirmation or block on revocation. No callback is an authentication proof: only provider token-context checks and successful USERINFO publish READY. The callback and all login backoff waits run outside the session invocation lock. The old two-gate launcher is consumed and is not a migration path for this API.

The minimum request reserves are4 before discovery,3 before device creation,2 before token acquisition/refresh,1 for USERINFO. Transient verification errors can still exhaust a finite budget; no claim of guaranteed provider success or automatic budget renewal is made. Existing expired/ambiguous/revoked/frozen sessions retain their original guards and history. This patch does not grant a new budget to tr33g8bg.
